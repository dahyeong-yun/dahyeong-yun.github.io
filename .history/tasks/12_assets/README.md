# #12 브랜드 방향 — 결정 자료

[12_branding_direction.md](../12_branding_direction.md) 를 진행하면서 만든 비교 자료입니다.
결정 근거를 남기려고 보관합니다. 사이트 빌드와는 무관하고, 지워도 사이트는 그대로 동작합니다.

## 결정된 것

| 항목 | 결정 | 근거 |
| --- | --- | --- |
| 강조색 | `#0066cc` / `#0a84ff` **유지** | 후보 5종을 실제 화면에 입혀 비교한 뒤 현행 유지 |
| 마크 | **불완전한 격자** — 꼭짓점 11, 엣지 18 | 각진 기하 형태에 점과 선, 닫히지 않은 모양 |
| 파비콘 | 격자 안의 **삼각형 하나** (노드 1-6-7) | 넷 중 유일하게 떼어내도 다른 아이콘과 안 겹침 |
| 마크 색 | 검은 바탕 + `#0a84ff` 삼각형 | 밝은 탭 줄에서 검은 사각형이 가장 빨리 찾힘 |
| 헤더 | 마크 28px + 워드마크 | 격자가 28px 에서 읽히므로 조각이 아닌 원본을 씀 |

`P` 자 · 프리즘 · 책갈피 · 나이테는 모두 탈락했다. 마크 결정 과정은
`mark-candidates.html` 과 `geo/` 에 남아 있다.

## 파일

### 강조색

- `accent-candidates.html` — 후보 5종(현재 파랑 · 인디고 · 딥 틸 · 테라코타 · 포레스트)을
  실제 글 페이지 축소판에 입혀 라이트/다크로 비교. 브라우저로 열면 됩니다.
- `contrast.mjs` — WCAG 대비 계산. 5종 모두 라이트/다크 양쪽에서 AA 통과 확인용.
- `de.mjs` — CIE Lab 색차(ΔE) 계산. 강조색이 상태색과 충돌하는지 보는 용도.

### 파비콘 마크

- `mark-candidates.html` — 발행본. 16px 확대 이미지가 base64로 박혀 있어 단독으로 열립니다.
- `mark-candidates.src.html` — 읽기용 원본. 이미지 자리가 `__PRISM16__` 같은 자리표시자라 코드가 읽기 쉽습니다.
- `marks.mjs` · `pass2.mjs` · `final.mjs` — 마크 SVG 정의와 16px 래스터 스크립트.
  후보 SVG 의 path 데이터가 여기 다 있습니다.
- `sheet.mjs` — 16px 확대본을 한 장으로 이어 붙이는 스크립트.
- `sheet16.png` · `sheet16-pass2.png` — 16px 비교 시트(1차 / 2차).

### 격자 마크 — 채택된 안 (`geo/`)

- `geo-marks.html` — 각진 격자 A·B 두 안과 파비콘 축약형 6종 비교. 제미나이 프롬프트도 여기 있다.
- `polymorlog-mark.html` — **최종안.** B 안에서 삼각형을 떼어내는 과정과 색 채움 네 벌.
- `geo.mjs` · `geo2.mjs` — 격자 후보 A·B·C·D 와 재작업본. 노드/엣지 목록이 여기 있다.
- `fav.mjs` — 육각 실루엣 기반 축약형 6종의 16px 시험.
- `tri.mjs` — B 안에 닫힌 삼각형이 몇 개인지 세고 넓이·중심거리·납작함을 잰다.
- `trifav.mjs` · `fill.mjs` — 삼각형 셋을 파비콘으로 만들어 비교하고, 채움 색 네 벌을 시험한다.
- `header.mjs` — 격자가 헤더 크기(24·28·32px)에서 읽히는지 확인.
- `*-sheet*.png` — 위 스크립트들이 만든 비교 시트.

### 실제 파일 생성

- `build-icons.mjs` — **`public/` 의 네 파일을 만드는 생성기.** 마크 좌표와 삼각형 선정
  이유가 주석에 있다. 좌표는 테마의 `SiteMark.astro` 와 같은 값이므로
  한쪽만 고치면 로고와 파비콘이 어긋난다.

## 이 작업에서 확인된 것

**색을 바꾸려면 8개 토큰 + 설정 1곳 + 이미지 4장을 고쳐야 합니다.**
12번 문서 8절은 `global.css` 두 곳이라고 적었지만, 파랑에서 파생된 토큰이 블록마다 4개씩
(`--color-accent`, `--color-accent-hover`, `--color-header-active-bg`, `--color-badge-bg`)
있고, 여기에 `blog.config.ts` 의 `theme.themeColor` 와 `public/` 이미지 4장이 더 붙습니다.
다만 `global.css` 밖에 하드코딩된 파랑은 한 군데도 없습니다.

**다크 정의가 두 벌입니다.** 테마는 `:root[data-theme="dark"]` 와
`@media (prefers-color-scheme: dark)` 에 같은 값을 각각 적어 둡니다. 한쪽만 고치면
토글로 다크를 켠 사람과 OS 가 다크인 사람이 다른 색을 보게 됩니다.

**`blog.config.ts` 의 `theme.colorScheme` 은 죽은 설정입니다.**
테마 전체에서 이 값을 읽는 코드가 없습니다(`types.ts` 의 타입 선언 한 줄이 전부).
초기 테마는 `BaseHead.astro` 에서 `localStorage` → OS 설정 순으로 정해지므로,
`colorScheme: 'dark'` 로 적혀 있어도 실제 기본값은 방문자의 OS 설정입니다.

**강조색은 `--color-error` 와 부딪힐 수 있습니다.**
`global.css` 의 `.wikilink-broken`(아직 안 쓴 문서를 가리키는 위키링크)이 `--color-error` 를 씁니다.
정상 위키링크는 강조색이라 둘이 한 문단에 나란히 놓입니다. 그래서 붉은 계열 강조색은
"쓴 글"과 "안 쓴 글"을 구분 불가능하게 만듭니다 — 테라코타 후보가 ΔE 7 로 탈락한 이유입니다.

**16px 에서 도형 안쪽을 가르면 반드시 실패합니다.** 이번 세션에서 네 번 더 확인했습니다.

| 시도 | 16px 에서 |
| --- | --- |
| 아이소메트릭 큐브의 면 가르는 선 (굵기 5 → 3 → 2) | 육각형이 세 조각으로 갈려 자동차 엠블럼 |
| 육각형 Y자 음각 (굵기 8) | 위와 같음 |
| 육각형 굵은 Y자 음각 (굵기 9) | 위와 같음 |
| 삼각형 꼭짓점의 노드 세 개 | 도형이 파먹혀 벌레처럼 뭉개짐 |

12번 문서 4절이 겹친 두 원·반원+각진 면에서 관찰한 것과 같은 실패입니다.
이제 규칙으로 봐도 됩니다 — **16px 에는 바탕 하나와 도형 하나만 들어갑니다.**
점과 선은 큰 마크가 담당하고, 파비콘은 실루엣만 가져갑니다.

**떼어낼 삼각형에는 조건이 있습니다.** B 안의 닫힌 삼각형은 넷인데 셋이 탈락했습니다.
가운데 것은 넓이가 나머지의 절반도 안 돼 떼면 묻히고, 위쪽과 왼쪽 둘은 한 변이 거의
수직이라 떼어내면 **재생 버튼**으로 읽힙니다. 남은 오른쪽 위 것만 세 변이 모두 기울어
어떤 표준 아이콘과도 겹치지 않습니다. 같은 이유로 각도를 바로 세우지 않았습니다.

**격자는 24px 까지 버팁니다.** 헤더에 아이콘이 아니라 마크 원본을 넣을 수 있었던 근거입니다.
