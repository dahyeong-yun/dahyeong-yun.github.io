커넥션을 얻은 순간부터 반납할 때까지의 시간. **DB 쿼리 실행 시간보다 넓은 구간**이다.

[[HikariCP 설정]]의 추정 식에 그대로 들어가는 값이라, 이 시간이 길어지면 같은 TPS를 감당하는 데 더 많은 커넥션이 필요해진다.

## 쿼리 시간과 벌어지는 이유

스프링의 `@Transactional` 은 **메서드 시작 시점에 커넥션을 획득하고, 메서드가 완전히 끝날 때까지 반납하지 않는다.**

그래서 트랜잭션 범위 안에 DB가 아닌 작업이 들어가면 그만큼 커넥션이 묶인다.

- OAuth 인증 같은 외부 API 호출
- 알림톡 발송

외부 API가 2초를 끌면 DB 쿼리가 1ms에 끝났더라도 커넥션은 2초 동안 잡혀 있다.

## 줄이는 방향

풀을 키우는 것과 점유 시간을 줄이는 것은 같은 목표에 도달하는 두 가지 길이다.
후자는 코드 구조의 문제라서, 트랜잭션 안에 무엇을 두는지를 조정하는 일이 된다.

줄이지 않고 두면 풀이 마르는 속도가 빨라지고,
그 끝은 [[커넥션 풀 고갈이 서버 전체 장애가 되는 경로]]다.
